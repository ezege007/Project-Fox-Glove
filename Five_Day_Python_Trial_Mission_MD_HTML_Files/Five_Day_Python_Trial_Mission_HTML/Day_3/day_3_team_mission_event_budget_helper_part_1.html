DAY 3 · TEAM MISSION · PART 1

Event Budget Helper — Build, Test and Integrate

Teams of 2–4 expand the Day 2 budget idea into a small shared program. The challenge is component ownership, testing, review, handover, and integration.

Mission Goal

A — participant_cost

def participant_cost(attendees, food_per_person, transport_per_person):
    pass

Return attendees * (food_per_person + transport_per_person).

B — event_total

def event_total(attendees, food_per_person, transport_per_person, venue_cost):
    pass

Call participant_cost, add venue_cost, and return the total.

C — budget_status

def budget_status(budget, total):
    pass

Return "Within budget" when total <= budget; otherwise return "Over budget".

D — event_summary

def event_summary(event_name, total, status):
    pass

Return an exact readable summary using the supplied values.

Team Rule: Divide the Work, Not the Understanding

By the end of Day 3, every learner must have:

  • one attributable code contribution;
  • at least one test result;
  • at least one review action;
  • enough understanding to explain what their component receives and returns.

Recommended Team Workflow

  1. Read all four function contracts together.
  2. Assign clear component ownership.
  3. Predict the full program flow before coding.
  4. Build and test components separately.
  5. Write short technical handover notes.
  6. Review a teammate component without taking it over.
  7. Integrate one component at a time.

Minimum Component Tests

  • participant_cost: normal attendees and zero attendees.
  • event_total: normal attendee cost plus venue, and zero attendees with a venue.
  • budget_status: below budget, exact budget, and over budget.
  • event_summary: required example and one different event.

Short Handover Format

Component: budget_status
Returns: "Within budget" when total <= budget, otherwise "Over budget"
Tests: below budget, exact budget, over budget
Issue: none

Integrate in Small Steps

Run a test after connecting each step.

Day 3 Evidence Required

  • each learner's code contribution;
  • at least one test result per learner;
  • one review action per learner;
  • one short handover note per learner;
  • the first integrated Day 3 program;
  • any unresolved issue to continue on Day 4.

Day 3 finish line: clear ownership, tested components, visible contribution, review evidence, and a first integrated version.
