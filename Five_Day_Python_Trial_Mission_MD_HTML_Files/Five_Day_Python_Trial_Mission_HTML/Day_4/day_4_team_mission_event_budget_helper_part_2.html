DAY 4 · TEAM MISSION · PART 2

Event Budget Helper — Integrate, Cross-Test, Improve and Inspect

Day 4 turns the team's first integrated version into verified evidence. Finish the program, test important cases, cross-test with another team, improve carefully, retest, and prepare for inspection.

Mission Goal

Finish and verify the shared Event Budget Helper with these four components:

participant_cost(attendees, food_per_person, transport_per_person)
event_total(attendees, food_per_person, transport_per_person, venue_cost)
budget_status(budget, total)
event_summary(event_name, total, status)

1. Finish the Four Components

Rerun each component's Day 3 tests before integration. If a component fails, record the failing input, expected result, and actual result before changing code.

2. Run Shared Acceptance Tests

  • Normal event — standard participant and venue costs.
  • Zero attendees — venue cost must still be included.
  • Exact budget — total == budget must return "Within budget".
  • Over budget — total > budget must return "Over budget".
  • Summary output — use the supplied event name, total, and status.

5. Implement or Verify an Improvement

Every learner must implement or verify at least one documented improvement.

  • correct a wrong arithmetic operation;
  • correct an exact-boundary condition;
  • fix summary formatting;
  • repair integration between components;
  • add a missing test;
  • verify that a peer fix solved the reported failure.

6. Retest After Every Fix

  1. Rerun the previously failing case.
  2. Rerun at least one related case that passed before.
  3. Confirm that the fix did not create a regression.

7. Prepare for Coding Mentor Inspection

Each learner should be ready to explain:

  1. what component or change they owned;
  2. what requirement applied;
  3. what problem or test they worked on;
  4. what they changed or verified;
  5. what evidence proves it works;
  6. one area of teammate code they reviewed.

Use this explanation pattern:

Requirement → observed problem → change → evidence

Final Team Submission

Shared team evidence

  • final integrated program;
  • final acceptance-test evidence;
  • cross-team defect reports;
  • corrected and retested version;
  • shared final result.

Individual evidence

  • attributable code contribution;
  • test evidence;
  • one review or cross-test action;
  • one documented improvement or verification;
  • handover/contribution record;
  • explanation during mentor inspection.
